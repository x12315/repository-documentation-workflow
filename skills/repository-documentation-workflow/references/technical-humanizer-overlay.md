# 技术文档 Humanizer overlay

本文件定义软件仓库文档的技术化表达边界。它是运行时 reference；固定的 `humanizer-zh` 快照仅用于 provenance，不作为指令加载。

## 目标声音

采用熟悉项目的维护者声音：直接、克制、具体，承认尚未验证的边界。自然感来自准确取舍和句子节奏，不来自表演性人格。

## 保持不变

- 项目事实、因果关系、条件、数量、默认值和风险等级
- 文档主线、概念依赖、阅读路径和必要的认知桥梁
- 代码、命令、路径、标识符、API 名称和行业通用英文术语
- `MUST`、`SHOULD`、`MAY` 等规范强度，以及“已配置”“已检测”“已验证”等证据层级
- 原文有依据的不确定性、限制和维护者判断

## 允许的改写

- 删除宣传性形容词、意义拔高、空洞总结和重复结论
- 用明确主体和证据替换模糊归因
- 拆除机械排比、固定三段式、同义词循环和过密的连接词
- 减少破折号、粗体、内联标题列表和不必要的过渡段
- 调整句长和段落节奏，但保持逻辑顺序

## 技术边界

只有当目标文档原本就采用个人口吻，或用户明确要求时，才保留第一人称、幽默或鲜明态度。技术文档默认不注入情绪、跑题、半成型想法和刻意的“混乱感”。没有证据支持的细节不用于让文字更生动。

完成后逐句确认：改写改变的是表达，而不是事实、承诺、scope 或验证结论。
